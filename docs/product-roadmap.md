# Product opportunities after interface clarity

Updated November 1, 2026. The Explorer and Engineering refinement are shipped.
[Product Room](product-room.md) adds three buyer-facing destinations and a
crank customer-project flow, using the unchanged Explorer. The public template
remains static. [Studio](studio.md) now provides the crank product editor,
part/document association, inquiry configuration, isolated buyer preview and
reviewed local demo releases. Hosted content uses an exported release and the
existing GitHub deployment pipeline. [Customer projects](studio-customer-projects.md)
connects buyer inquiries to seller drafts, reviewed quotation issuance, replies,
version comparison and next-step acknowledgement.

## Product Room

The Room connects three sample buyer questions to relevant views, product
documents and one next action. Its request flow carries the product, exact model
revision and optional selected part, document or chapter. Saved-view capture
is reserved for a later iteration.
The approved second phase adds browser-local inquiries, immutable quotations,
version-bound changes, sample replies, comparison and customer next-step requests.
The component catalog shares the actual workspace controls. These are sample
commercial records, not live manufacturer transactions.

Use the existing JSON controller. `captureView` supports settled exploration and
paused manual operation, not arbitrary running-tour poses. Bookmarks require an
exact model revision; never silently remap comments to a different geometry export.
Durable sharing, accounts and customer data belong to the host's future backend,
not the public Explorer template. Demonstration persistence is limited to the
current browser; no backend, login or cross-device sharing is implemented.

## Annora Studio

The first authoring release covers product copy/facts, part/document links,
existing presentation entry points, inquiry prompts and release review. Extend
model readiness, materials and short-story authoring after this workflow is reviewed.

A Story Composer can select a component and camera, bind an approved 2–3 second
action, supply a short explanation and preview its held endpoint. Its output
should be the existing model/tour package, not a second animation runtime.
AI assistance may propose copy or views grounded in supplied material; engineering
relationships and motion require review. Measure preparation effort on another
customer product before deciding which authoring tasks to automate.

## Evidence and order

1. Review the complete crank inquiry-to-revised-quotation journey and shared components.
2. Build the derived Studio editors around shared versioned content, preserving
   the existing Explorer.
3. Validate product authoring and the shared buyer/seller customer-project loop.
4. Then plan durable sharing and the first real customer pilot. Real accounts,
   customer data, integrations and sales insight require future Annora services.

This order supersedes the earlier proposal to run the real-product pilot before
Studio. The user explicitly requested Product Room and Studio first.
