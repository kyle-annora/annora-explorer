## Product outcome

Help a seller explain a product, help a buyer ask a precise question while
inspecting it, and let both return to the exact evidence to resolve the next
decision. Support customers that already have a viewer as well as Annora's own
Explorer. Success includes preparation effort and task completion, not only
visual quality or a successful build.

Explorer remains the inspection surface. Product Room remains the buyer's
workspace. Studio remains the seller's workspace. New capabilities extend these
surfaces through prepared content and host contracts; they do not create another
renderer, project store or global navigation system.

| User's job | Information needed | Relevant capability |
| --- | --- | --- |
| Engineer evaluating a detail | Exact part/view/drawing revision; what remains unknown | Contextual requests, technical-view steps, question resolution |
| Buyer comparing an offer | Approved alternative, quantity, included/excluded scope, quote version | Option comparison and explicit quote-scope mapping |
| Seller preparing the next discussion | Relevant explanation, unanswered items and one next action | Customer follow-up and existing project workspace |
| Delivery operator or integrating agent | Source readiness, supported functions, reproducible package and host contract | Onboarding workbench and integration kit |

These jobs inform progressive disclosure; they do not add a mandatory role
selection screen. Keep the current inquiry intent rules: application review may
leave quantity unknown, while a quotation request and issued commercial terms
retain their applicable validation.

## Recommended decisions

1. Keep browser-local fake data for this program. Define durable-service contracts
   without building accounts, email, permissions or a production database.
2. Prove the next end-to-end slice on the crank. Use SK08/linkrods for real drawing
   references; do not invent a crank engineering drawing.
3. Start option comparison with two seller-approved scope alternatives within
   one product release. Geometric configurations require actual prepared assets.
4. Use at most four active agents including the integration owner. Freeze each
   shared contract before parallel buyer and seller work.
5. Review and publish one coherent journey at a time. New feature breadth never
   substitutes for history, recovery, mobile and live-target evidence.

The next execution unit is W0 followed by W1 in [the execution plan](execution.md).
Its result is a focused follow-up that returns a buyer to the same project and
original inquiry evidence, then to an exact quotation or current clarification.
Confirmed inquiries remain immutable. Later packages remain separate reviewable deliveries.
