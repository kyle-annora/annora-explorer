# SK08 paired source reference

This package is a second, independently licensed example of an existing STEP
solid paired with a drawing generated from that exact source. It is a shaft
support, not a complete bearing assembly. All seven selectable regions map to
the single real support body `sk08-body`; holes and the slot are features, not
invented assembly parts.

## Source and status

- STEP: FreeCAD parts library, author **hasecilu**, CC BY 3.0, pinned at commit
  `f5ca01cdcaa2f69b9295a6382719c2d90628780c`.
- Source file: `Mechanical Parts/Mountings/SK08/SK08-SK08.step`. The exact source
  bytes are retained as `sk08.step` and agree with the upstream SHA-256.
- Drawing: `pzfreo/dw-examples`, commit
  `c4c72a71c6440f0c824678660b59d0474f105e71`, generated by draftwright v0.2.5
  from that STEP. `source.pdf` is the unchanged original asset.
- The source is **unreviewed**. General tolerance and some chamfer annotations
  are absent. Keep `source-review.json` with the asset. No manufacturer revision,
  material specification or manufacturing approval is supplied.

`source-readme.md` preserves the upstream attribution and licensing context.
`LICENSE.txt` carries the exact CC BY 3.0 text. The model and derived drawing
retain that attribution and license; the application license does not replace it.

## Pages and identities

`reference.pdf` contains two pages:

1. The original source page, without changing its content.
2. A clearly labelled Annora layout that enlarges two vector crops from page 1.
   It adds no dimensions, tolerances or engineering revision, and is not to scale.

The authored reference edition is `annora-reference-1`; the mapping edition is
`annora-sk08-map-1`. These are asset/presentation identities, not manufacturer
engineering revisions. `manufacturerRevision` remains null. The original and
derived PDF have separate asset IDs and SHA-256 identities in `package.json`.

`package.json` is the DrawingPackage v2 contract. `drawing.json` retains the
legacy preview metadata. Regions use unrotated page-top-left coordinates in
PDF points; camera targets use model coordinates in meters. `sheet-1.svg` and
`sheet-2.svg` are vector fallback exports of the same PDF pages.

## Geometry and authored mapping

The original STEP contains `#7 PRODUCT('SK08',...)` and one solid,
`#15 MANIFOLD_SOLID_BREP`. It explicitly declares millimeters in `#1600`.
The presentation conversion is `[x,y,z] mm -> [x,z,-y] / 1000 m`.
The resulting mesh is `sk08_body`, imported as part `sk08-body`, model `sk08`.

- Shaft bore: cylinder `#427`, radius 4 mm, source axis through
  `(21, -14, 20)` mm.
- Cross-bore: cylinder `#212`, radius 3.5 mm, source axis through
  `(12, -7, 27.8)` mm.
- Base mounting holes: cylinders `#1079` and `#1109`, radius 2.75 mm,
  through source locations `(5, -7, 6)` and `(37, -7, 6)` mm.

Camera focus points identify these features but are not measurement results.
The satin display finish is illustrative. No source operating motion, assembly
separation or guided tour is invented. The prepared package has 3,072 triangles,
one draw mesh and a 34,074-byte gzip GLB.

## Reproduce and verify

Run commands from the repository root. Use `occt-import-js` version `0.0.23`
in an isolated tools directory; no runtime CAD converter is added to the app.

```sh
node content/drawings/sk08/source-tools/tessellate-step.cjs /path/to/occt-import-js content/drawings/sk08/sk08.step /tmp/sk08-mesh.json
python3 content/drawings/sk08/source-tools/make-preview-glb.py /tmp/sk08-mesh.json /tmp/sk08.glb
npm run import:model -- --source /tmp/sk08.glb --definition content/drawings/sk08/model-definition.json --out /tmp/sk08-prepared-review
python3 content/drawings/sk08/source-tools/make-reference-pdf.py
node content/drawings/sk08/source-tools/verify-source.mjs
```

The PDF preparation requires PyMuPDF and reportlab. When deliberately rebuilding
an asset, review it, regenerate SVG fallbacks and update the exact asset hashes
and package edition. Never relabel an altered PDF as the unchanged source.
The checked-in model metadata is importer output and must not be manually edited.

Verification performed: upstream STEP byte comparison; one-body import with no
warnings except the intentionally absent tour; both PDF pages visually inspected;
derived page 1 rendered pixel-identically to `source.pdf`; seven overlay regions
checked against the original PDF vectors; v2 schema and exact part registry
validated. Browser/mobile integration is validated by the host application.


## Fictional document B for workflow acceptance

`demo-revision-b.pdf` is a clearly labelled Annora demonstration edition. Page 1
retains the original source drawing; page 2 swaps the two enlarged source views
and adds a request to confirm bore inspection scope. The STEP/model, dimensions
and manufacturing approval status are unchanged. It tests actual PDF version
import, manual reassociation and quotation history; it is not a supplier revision.
`source-tools/make-demo-revision.py` reproduces it using PyMuPDF and reportlab.
The source attribution and CC BY 3.0 notice are retained on the PDF.
